# Sujithra Yesurathinam | Ideas into Action

A seven-section portfolio with a bold plum, coral, and warm-ivory visual identity, a portrait-led homepage, a current-focus snapshot based on documented responsibilities, larger readable type, and responsive navigation. Pages use animated entrance transitions, a rotating editorial orbit in page headers, a reading-progress thread, scroll-triggered reveals for copy, cards, diagrams, and resume sections, staggered timelines, and subtle hover motion; visitors who prefer reduced motion receive reduced animations. On touch devices, a horizontal swipe navigates through the pages in the same order as the navigation links; floating previous/next arrows provide an additional way to browse. A corner counter records public browsing sessions through the included Node.js server and stores the running total in `.portfolio-data/visits.json` by default. A session is counted once when a visitor first opens the site in a tab; page navigation and refreshes in that tab do not add more visits. It does not identify people. The Learning page presents qualifications in an animated timeline and features an animated NPTEL certificate gallery (`assets/images/nptel-*.png`). The About page maps key career disciplines and includes a personal-interest section; Strategy & Operations pairs an execution-cycle diagram with a streamlined working-signature pathway across analysis, coordination, and communication. Learning connects skills in a toolkit map, Research presents an editorial bibliography, and Projects uses a guided-project pathway instead of repetitive card grids. On the Contact page, the email link and message form open a pre-addressed Gmail compose page in the current tab; visitors may need to sign in to Gmail, then review and send the draft. The page also links to LinkedIn. The resume page offers concise and detailed formats generated from shared site data. Its PDF export control appears only in the local portfolio preview; a public static page cannot securely prevent visitors from using their browser’s own print or save features on content that is visible to them.

## Run locally

Install Node.js, then run `npm run dev` in this folder and open [http://127.0.0.1:4173](http://127.0.0.1:4173). Development mode always displays zero and never changes the live visitor total. The server listens on `0.0.0.0` by default so deployment platforms such as Render can reach it; it prints the local preview address as `127.0.0.1`. To restrict a local run to this computer, set `HOST=127.0.0.1` before starting it. The server has no package dependencies. In Windows PowerShell, if script execution policy blocks `npm.ps1`, use `npm.cmd run dev` instead; this invokes npm's Windows command launcher without changing the system execution policy.

For deployment, use `npm start` as the start command. This enables the counter only for public hostnames; requests through localhost and private IP addresses do not increment or display the live count. One visit is counted per browser-tab session, not per page; opening a new session can count again. This is a session-based visit estimate, not a count of unique people, and automated browsers may also be counted. By default, the total is stored in `.portfolio-data/visits.json`. Deployment filesystems may be temporary, so attach persistent storage and set `VISITOR_COUNT_FILE` to a file on that storage (for example, for a Render disk mounted at `/var/data`, set it to `/var/data/visits.json`). Without persistent storage, the count may reset when the service restarts or is redeployed. Static-only hosting cannot run this counter API.

## Edit content

Update profile details, career history, academic history, focus areas, tools, hobbies, projects, books, and publications in `assets/js/content.js`. Both resume formats at `resume.html` are assembled from shared profile data, so content edits are reflected there automatically. The Resume icon in the header opens both formats to view. The “Save PDF” control is available when opening the portfolio through its local preview (`localhost` or `127.0.0.1`); it is hidden on a public host. This is a convenience restriction, not secure access control—restricting printing of public content requires a private, authenticated hosting service. Page layouts are in `assets/js/site.js`; design and responsive styles are in `assets/css/styles.css`.
